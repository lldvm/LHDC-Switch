# 更新记录

## 2.4.3 · 发送积压与自动码率平台期修正

- 固定、自动模式共用的发送端只检查媒体时钟原有截止时间，取消按上一包实际发送时间追加的逐包等待，避免 USB / 控制器延迟叠加。
- 超过发送期限 120 ms 的旧队头包会被跳过，保留新声音；每个跳过包都计入本机丢弃及 ABR 反馈。120 ms 是主机处理预算，不是端到端延迟保证。
- 蓝牙事件循环使用 MMCSS Pro Audio，与编码及 USB 写线程保持一致。
- 短暂排队抖动不再反复清零整个升档观察期；持续积压仍阻止升档并在拥塞时降档。
- 同一档位探测失败按 15 / 30 / 60 秒逐步退避，稳定成功后清除失败历史；经 700/750/800 小步升向 900 时不再沿用 500→900 大跨度的 20 秒等待。
- 保留所有固定目标、自动上限及耳机能力 / MTU 限制。固定模式不会自动降低目标。
- 自动检查通过：LHDC 编码器 / ABR 15 项、分包 11 项、蓝牙主机 73 项、流水线 24 项、运行循环 2 项、控制器 47 项及真实 IPC。耳机端试听仍待完成。

## 2.4.2 · 首次 GitHub 公开发布

- 保留 AOSP Rust 编码器，新增真实固定 700 / 750 / 800 kbps 以及对应自动上限。
- 编码器接口传递精确目标，不把新选项映射成 900 档；保留耳机能力与 MTU 限制。
- 包含 2.4.1 的积压恢复修正：统一发送截止时间，正常分包不再持续误判拥塞，失败升档仅暂时退避。
- 包含实时状态、托盘、按需音量确认及实验耳机功能面板。
- 公开完整控制器 / 修改引擎源码、锁定依赖、来源致谢、许可与操作 / 构建文档。
- 发布包采用示例配置和独立配置脚本，不包含任何本机配对记录、设备实例、日志或驱动备份。

已验证：控制器 47 项、Rust 编码器定向单元 12 项、分包集成 11 项；界面菜单与真实 IPC 检查。用户已确认前一 Rust 基础版本能正常播放，新档位仍需在各自硬件环境评估。
