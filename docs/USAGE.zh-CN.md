# 使用说明

## 环境与兼容性

- Windows x64，.NET Framework 4.8。开发使用的 Intel AX201 的 USB ID 为 `8087:0026`；程序拒绝其他 ID。
- 耳机须支持 LHDC v5。实测为 OPPO Enco Free4 丹拿版。耳机功能写入只允许产品 ID `068C10` / `06C010`。
- 切换和恢复蓝牙驱动需要管理员权限。接管会独占整个蓝牙控制器，其他蓝牙外设会断开；Wi-Fi 功能不会被切换。
- 解压到普通可写目录，保留 `LHDC-Switch.exe.config`、`engine/`、`firmware/`、全部许可证。不要从压缩包内部运行。

## 配置目标设备

首次发布包不含任何开发者的设备地址、配对密钥、驱动备份、使用设置或运行日志。必须生成自己的 `settings.json`。

先在 Windows 中识别耳机地址：设备管理器 → 蓝牙 → 对应耳机设备 → 属性 → 详细信息 → “Bluetooth 设备地址”；若无该条目，查看设备实例路径中 `DEV_` 后的 12 位十六进制数，并整理为 `AA:BB:CC:DD:EE:FF`。不要误填蓝牙控制器自身地址。

双击 `配置设备.cmd`，或在 PowerShell 中执行：

```powershell
.\configure.ps1 -Address 'AA:BB:CC:DD:EE:FF' -Headphone '我的 LHDC 耳机'
```

脚本查询当前 `8087:0026` 设备的实例路径，检查地址格式并生成设置；它不会改驱动。存在多个同 ID 设备时先用 `configure.ps1 -ListDevices` 查询，再显式提供 `-InstanceId`。仅有上述格式匹配不代表所有硬件修订均兼容。

也可复制 `settings.example.json` 为 `settings.json`，填写实际 `InstanceId`、`Address` 和显示名称。示例中的 `CONFIGURE_ME` 与零地址不能用于连接。关闭本目录程序后再修改设置。

## 连接与音源

先在耳机官方应用中确认 LHDC / 高清音频已开启，断开手机占用。耳机首次连接本引擎需进入配对模式；引擎的配对记录与 Windows 分开。

以 **48 kHz、自动最高 700** 开始。勾选“只在耳机播放”时，需先安装 VB-CABLE。可打开官方 `https://vb-audio.com/Cable/`，或使用包内 `dependencies/VBCABLE_Driver_Pack45.zip` 的完整原版安装包；按官方说明运行独立安装器并重启。VB-CABLE 为 VB-Audio 的 donationware，来源 www.vb-cable.com，欢迎向原作者捐赠。项目不静默安装、修改或重新签署它。

点击“连接 LHDC”后接受 UAC。确认界面显示实际 LHDC 编码及实时发送数据，再开始播放。默认音频会临时切至 CABLE Input，恢复时还原三种默认播放角色。应用若固定输出到物理扬声器，需要在 Windows 音量混合器改回“默认”或 CABLE Input。不要给 CABLE Output 开启“侦听此设备”。

应用框留空采集系统声音；填写 `music.exe` 等进程文件名只采集指定应用。取消“只在耳机播放”会启用回环复制，扬声器可能同时出声。

## 码率、卡顿与音量

固定选项：400 / 500 / 700 / 750 / 800 / 900 / 1000 kbps；自动选项分别限制最高码率为这些值。自动最高值是上限，不保证持续达到。耳机能力、实际 MTU、采样率可能进一步限制目标。切换音质后重新连接生效。

自动模式依据本机队列时长、最老包等待时间、新增发送 / 入队丢弃降档；恢复后重新探测，不会把一次失败永久锁成低上限。媒体时钟来自累计音频采样数，临时积压能逐步排空。

若卡顿：先降至自动 500 / 700，靠近电脑，减少遮挡；可将 Wi-Fi 切至 5 / 6 GHz 并减少其他 2.4 GHz 干扰。高采样率和固定 900 / 1000 不保证更稳。程序没有同时占用多个经典蓝牙频点发送、超额发射功率或厂商专有增强开关。

- 实时编码码率：编码器的当前目标；用它确认切档。
- 实时发送速率：含 RTP 等开销的本机发送量，两者不必相等。
- 音频积压 / 等待：本机尚未提交的音频，不包含耳机内部缓存。
- 本机丢弃 / 发送停顿：不能据此判断所有无线重传或耳机欠载。

连接后可拖动音量滑块，显示等待耳机 AVRCP 确认；平时不持续额外查询音量。没有回包时不应把滑块请求值当成耳机已确认值。

## 耳机功能面板

高清音频、空间音频、游戏模式、双设备和 ANC 控制属于实验功能。RFCOMM 辅助程序使用 Windows 蓝牙栈，需要先断开 LHDC 并恢复 Windows 蓝牙，再连接耳机、读取设置。面板会检查产品 ID 和能力，写入后读回验证；部分模式会要求重连，高清与空间音频可能互斥。写入确认不等于所有固件均生效。不提供固件升级。

## 停止与恢复

“断开并恢复蓝牙”停止音频并恢复原驱动和播放设备。关闭窗口默认最小化至托盘，仍会继续播放。完全退出请用托盘菜单“退出并恢复蓝牙”。不要在连接期间删除目录、覆盖程序或强制结束后台进程。

程序在第一次切换前导出原驱动，保存 `data/pending-restore.json`。连接失败、未在时限内确认播放、引擎退出或主界面消失会触发恢复尝试。只有核对设备、原 INF / 版本 / 服务和音频恢复成功才清除待恢复记录。

断电、系统崩溃或强杀恢复进程后，重新打开程序并执行恢复，或运行 `恢复蓝牙.cmd`。恢复失败时保留整个 `data/` 与驱动导出备份；这些记录属于自己的机器，不要套用别人的驱动备份。

仍无法恢复时，在设备管理器仅定位配置中的那块 Intel USB 蓝牙设备，卸载设备（不要删除原 Intel 驱动包），再“扫描检测硬件改动”；必要时用自己的导出备份或电脑厂商蓝牙驱动恢复。不要对 USB 集线器或 Wi-Fi 设备执行此操作。

## 日志与反馈

日志仅保存在本机 `data/`。它可能含设备地址、实例路径、应用名、配对与驱动信息。反馈时优先提供版本、控制器 USB ID、耳机型号、音质设置和现象；上传日志前自行删除个人信息，绝不要上传 `link_keys.txt`、`le_audio_bonds.tlv`、完整配对目录或驱动备份。
