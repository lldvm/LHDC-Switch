# LHDC Switch 2.4.3 Rust engine changes (2026-10-27)

Upstream: https://github.com/SeiyaFunaokaJP/A2DP-Windows-Bridge
Base: v2.0.1, commit 3a094af733c830a2f4f5bd7418e6c7ba1db94749.

The packaged a2dpwb-core.exe is a locally built modified version. The driver and upstream frontend remain original. Existing upstream copyright notices and licenses apply. New adaptive-policy code is provided under the same Apache-2.0 OR MIT license as the upstream codec crate.

Changes: replace the LHDC 400 kbps AOSP ABR table with a time-based congestion controller, bounded by a process-local requested ceiling and negotiated peer/MTU limits. Publish the live encoder target through the additive optional IPC field link.encoder_kbps. The maximum defaults to 400 unless the wrapper sets LHDC_SWITCH_ABR_MAX_KBPS. No changes to firmware, pairing, drivers, authentication or other codec policies.

Version 2.2: remember failed adaptive probes for the stream lifetime; longer high-rate dwell; query WLAN asynchronously outside the Bluetooth send thread; standard HCI radio diagnostics published as optional IPC fields; use link policy 0x0001 rather than 0x0005 when LHDC_SWITCH_ACTIVE_LINK=1, and exit Sniff during playback if needed. No vendor transmit-power overrides. The wrapper enables this session policy by default and offers a compatibility toggle. Additional source changes are in btstack-sys C/FFI wrappers, bt-host, core/adapter.rs and IPC; the combined patch includes them.

Version 2.3: publish accepted AVRCP absolute-volume confirmations through the normal volume event; reject invalid volume replies; collect host send-gap timing and WASAPI discontinuity counters as additive IPC fields; skip native core tray creation when LHDC_SWITCH_NO_TRAY=1. Other users of the engine keep its original tray behavior. The C# wrapper owns its own NotifyIcon and restoration lifecycle.

Version 2.4 A/B: both engines use RTP sample-clock pacing, a 20 ms initial encoder cushion, high-resolution per-thread waitable timers, a nonblocking L2CAP submission gate with recovery spacing, and a Windows BTstack run-loop derivative using monotonic QPC time and high-resolution timer events. The gate never sleeps on the Bluetooth thread. Host congestion feedback measures queued audio duration and oldest waiting time, plus newly observed queue/send losses; LHDC ABR uses these instead of raw packet count. Optional IPC fields expose these measurements, deadline lateness/rebases and actual encoder backend. These metrics cannot observe on-air retransmissions or the receiver buffer.

A keeps the pinned C-port encoder. B uses the AOSP Rust Context from DBeidachazi/liblhdcv5 commit 0df76b08196dc26e460404189279b17a7101af74, compiled natively on Windows. Vendored algorithm sources are unchanged; crate-type is rlib and the enclosing Cargo.lock fixes dependencies. lhdcv5-sys/src/aosp.rs provides error/length validation around the Rust API. B's build skips the C library entirely. The Linux C-wrapper ABR is not used. Both use the same transport and ABR policy. A/B offline probes produce identical bytes in all 24 tested cases; this is not an exhaustive codec conformance claim or a promise of improved audio.

Apply adaptive.patch at the upstream v2.0.1 repository root with git apply, initialize its pinned submodules and run build-ab.ps1 from the wrapper directory (repository in reference/). The combined patch now includes new source files and the AOSP source overlay; no separate manual copy of lhdc_abr.rs is needed. build-engine.ps1 builds the AOSP Rust backend by default. Build B using cargo build --release --locked -p a2dpwb-core-exe --features aosp-rust from reference/. Keep static CRT configuration enabled.

Tests include deterministic time/queue policy cases, actual C encoder rate changes with output-byte and MTU checks at all four sample rates, existing LHDC packet tests and IPC/pipeline tests. These do not certify earbud audio quality or radio stability.

Version 2.4.1 selects AOSP Rust for the primary release. The submission gate now consumes each packet's authoritative producer deadline rather than rebasing a second RTP sample clock; delayed packets can drain with the existing minimum recovery spacing. Both fixed and adaptive streams share this correction. LHDC congestion classification excludes a 20 ms packetization window and allows head-age jitter, so two normal 20 ms packets at 160 kbps no longer permanently block rate recovery. Downshifts are spaced at least 250 ms apart. Rates below the starting quality have a bounded 10 s recovery cooldown and 3 s upward steps. Failed probes block the failed stage for 60 s, then permit retry; they never permanently lower the configured session ceiling. Regression tests replay the user's normal low-rate queue conditions on the real Rust encoder, exercise temporary probe backoff, and simulate an 80 ms sender stall with 5/10/20 ms packets.

Version 2.4.2 adds true 700/750/800 kbps fixed targets and adaptive ceilings. The AOSP API layer gains a validated exact-rate setter using existing last_bitrate/update_frame_info state; stock-index changes compare actual values so a custom target and 900 cannot alias. The compression kernels remain unchanged. The Rust adapter exposes this setter, codec ABR inserts the custom stages within peer/MTU limits, and the controller passes validated per-process fixed/adaptive targets. Tests measure real encoded bytes at all four rates, custom/native midstream transitions, ABR recovery and peer caps.

Version 2.4.3 removes the post-send half-frame recovery gate: the producer media deadline is authoritative and USB/controller readiness delays must not receive another timer delay. Expired LHDC heads more than 120 ms behind that deadline are discarded before submission, preserving recent audio instead of rejecting new input behind a full stale ring; every skip counts as a local queue loss and reaches ABR feedback. Controller credits and can-send flow control remain intact. Fixed targets and codec code are unchanged. Regression cases model single-frame high-bitrate packets at all four rates, asynchronous readiness/timer delays, short-stall recovery, and full-ring stale-head removal/accounting. These are host-side checks, not radio or earbud certification.

Version 2.4.3 ABR follow-up: transient queue-pressure spikes no longer reset the entire upward stability window; sustained mild pressure still blocks probes and sustained/severe congestion still reduces the target. Per-stage failed-probe retries progress through 15/30/60 s, with failure history cleared after a successful stable retry. The 20 s high-rate dwell applies only to a large native jump (e.g. 500 to 900); fine 700/750/800 stages use the normal 5 s hold. Regressions cover the 480/500 plateau under periodic short jitter, sustained mild pressure, and progressive retry/reset. No bitrate target or peer/MTU limit is bypassed.

Version 2.4.3 scheduling follow-up: the Bluetooth event-loop thread uses a platform-provided, same-thread MMCSS guard, matching the existing encoder and USB ACL writer scheduling class. Registration failure is logged without preventing startup; the portable host crate remains free of Windows APIs.
